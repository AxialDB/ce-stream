# Release v0.2.0 — Gate 0 transaction-boundary capture

**Date:** 2026-08-15  
**Tag:** [`v0.2.0`](https://github.com/AxialDB/ce-stream/releases/tag/v0.2.0)  
**Issue:** Closes [#1](https://github.com/AxialDB/ce-stream/issues/1) (transaction-boundary checkpointing)

## Summary

This release fixes a data-loss bug where ce-stream could checkpoint a GTID after the first row of a multi-row MySQL transaction. Capture now buffers until **XID**, delivers at commit boundary, and persists the checkpoint only after the full transaction is acknowledged.

It also adds optional **transaction-mode** delivery (`CommittedTransaction` envelope), first-class **DDL** visibility, **compressed transaction** unpack, connect-time **capture gates**, and reliable **GTID resume** after crash (including servers with `gtid_purged` history).

## Upgrade notes

### Breaking (row mode timing)

Row CloudEvents are emitted **after commit**, not as row events arrive. Payload shape is unchanged; consumers that assumed intra-transaction streaming must adapt.

### New config

```toml
[source]
delivery_unit = "row"   # default; or "transaction" for one envelope per commit
```

See [`ce-stream.toml.example`](../../ce-stream.toml.example) and [`docs/library.md`](../library.md).

### MySQL prerequisites (enforced by default)

- `log_bin=ON`, `binlog_format=ROW`, `binlog_row_image=FULL`
- `binlog_row_metadata=FULL` (hard-fail if not)
- `gtid_mode=ON`

Lab escape hatch: `ce-stream --skip-gate-check`.

### From Git tag (recommended until crates.io)

```bash

```

GitHub Release assets are built in CI (**Linux** `ubuntu-latest` and **Windows** `windows-latest`, equal first-class targets). Verify `SHA256SUMS`.

|-------|----------|
