# Release v0.6.0: one contract for every source, and `ce-stream-postgres`

**Date:** not set (draft; 0.6.0 is not released yet)
**Tag:** [`v0.6.0`](https://github.com/AxialDB/ce-stream/releases/tag/v0.6.0)

## Summary

Implements [#19](https://github.com/AxialDB/ce-stream/issues/19). Each source answered the same questions in its own way: how a position is compared, how a consumer learns that the stream moved when nothing was delivered, how a seed lines up with the stream, what a table change looks like, how column names, types, and values travel, and what the gate reports. `ce-stream-core` now has one answer to each, for every source. MySQL and MongoDB moved onto it, and the old shapes are not kept beside the new ones. `ce-stream-postgres` is the first source written against it.

This release breaks the library API and the transaction-mode output. See [What changes for a consumer](#what-changes-for-a-consumer). The full list of names is in [`CHANGELOG.md`](https://github.com/AxialDB/ce-stream/blob/main/CHANGELOG.md).

## Added

- **`Delivery`.** Every source delivers one thing at a time through `ChangeSource::run_deliveries`: `Commit` (a committed transaction, or one part of it), `Progress { position }` (the stream passed a position with nothing in it for this consumer), and `Schema` (a table's definition). See [`delivery.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/delivery.md).
- **`covers`.** `source.covers(at, target)` is true when a stream that has delivered everything up to `at` has delivered everything up to `target`. An embedder compares positions without knowing the host: GTID sets on MySQL, cluster times on MongoDB, LSNs on PostgreSQL.
- **`Confirm`.** With `SourceConfig::checkpoint = CheckpointMode::OnConfirm` the checkpoint, and whatever the server retains for the consumer, moves only when the consumer calls `confirm.confirm(position)`. The default, `OnOk`, is as before: the callback's `Ok` is the confirmation. CLI: `checkpoint = "on_ok" | "on_confirm"` under `[source]`; `on_confirm` needs `delivery_unit = "transaction"`.
- **`SeedCut`.** `mark()` returns a position such that every transaction committed before the call is at or before it, and `wait_settled(mark)` returns when every transaction in flight at the mark has ended. It runs on a connection of the consumer's, never the stream's. The copy is the consumer's; ce-stream never reads source rows. `MysqlSeedCut`, `MongoSeedCut`, `PgSeedCut`.
- **`TableSchema`.** Column names, each column's `host_type`, `nullable` where the host says it, and `key`. MySQL delivers it on a table's first sight and when its columns change, PostgreSQL every time the server announces the table. MongoDB has no schema and delivers none. In row mode it is a CloudEvent of type `io.ce-stream.schema`.
- **Controls on every adapter.** `ControlKind` gains `Truncated`, `DefinitionChanged`, and `Message { prefix, content }`, and a control carries the table's host `identity` where it has one. MySQL gives typed controls for `DROP TABLE`, `RENAME TABLE`, `ALTER TABLE`, `TRUNCATE`, and `DROP DATABASE`, beside the SQL text in `ddl`.
- **`GateReport`.** `gate()` on every source returns `failures` and `warnings`, each naming the object and the fix.
- **Values.** One mapping for every adapter, in [`values.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/values.md). MongoDB rows have `types` beside the image, for the values whose form does not show their type.
- **`ce-stream-postgres`.** PostgreSQL 17+ logical replication (`pgoutput`) over its own protocol layer: SCRAM-SHA-256, TLS through `rustls`, no libpq. `PostgresSource`, `PgSeedCut`, `create_slot`, `drop_slot`, `slot_figures`, `catalog_tables`. CLI: `source.adapter = "postgres"`. Setup and the gate's checks: [`ops-e2e.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/ops-e2e.md#postgresql-prerequisites).
- **PostgreSQL failover slots.** `create_slot(options, slot, true)` makes a failover slot, and `alter_slot_failover` marks an existing one before the stream starts. `SlotFigures::failover` and `synced` show it. CLI: `failover = true`. After a promotion the stream resumes on the new primary when the checkpoint is at or before the point where the new timeline forked from the old one. `fork_point` gives that point, and `server_identity` the server's system identifier and timeline.
- **MySQL partition ids.** A row of a partitioned table carries the extension `partition_id`: the partition's place in the table's definition when the row was logged, with subpartitions as `partition * subpartitions + subpartition`. An update also carries `source_partition_id`, the partition the row left. A table that is not partitioned has neither.
- **MySQL: what a server can no longer send.** `server_missing(options, checkpoint)` asks a server, without starting a stream, which transactions it has purged that the checkpoint never received. `purged_missing` answers the same over sets the consumer already holds.
- **Avro `committed-transaction-v4`, `progress-v1`, `table-schema-v1`**, and `avro_encode::encode_delivery`. See [`avro.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/avro.md).
- **The checkpoint store has two steps.** `CheckpointStore::save` may run on every commit and survives the process. `CheckpointStore::sync` makes the last save survive the machine. `FileCheckpointStore` is in `ce-stream-core`, for any adapter.
- **Crash harness for PostgreSQL**: `scripts/crash-harness/postgres/`.

## Changed

- **The transaction-mode callback takes a `Delivery`**, not a `CommittedTransaction`.
- **MySQL fills `position` like every adapter.** `CommittedTransaction::gtid`, `gtid_set_after`, and `source_position()` are gone. A commit has `position.at = { "gtid" }` and `position.after = { "gtid": "<executed set>" }`.
- **A transaction with nothing for the consumer is a `Progress`**, not a commit with no events: on MySQL a transaction the include list leaves out or a statement such as `GRANT`, on MongoDB the idle resume token. `Progress` is not delivered in row mode; it still moves the checkpoint.
- **Transaction-mode output is a `Delivery`.** JSON: `{"commit": {...}}`, `{"progress": {"position": {...}}}`, or `{"schema": {...}}`. Avro: every commit is `committed-transaction-v4`; `Progress` and `Schema` have records of their own. v1 to v3 are read, not written.
- **Row mode delivers table definitions** as CloudEvents of type `io.ce-stream.schema`, on MySQL and PostgreSQL.
- **MySQL text is decoded from the column's own charset.** Before, the bytes were read as UTF-8, and anything else became a `hex:` string. Decoded: `utf8mb4`, `utf8mb3`, `ascii`, `latin1`, `latin2`, `latin7`, `cp1250`, `cp1251`, `cp1256`, `cp1257`, `koi8r`, `macroman`, `cp932`, `euckr`, `gbk`. A column in any other charset is left out of the row. A value that cannot be decoded is an error naming the column.
- **MySQL `ENUM` and `SET` are their labels, and `JSON` is text**, not a position, a bit mask, and binary. `BINARY`, `VARBINARY`, and `BLOB` are always `hex:` strings.
- **MongoDB rows hold the contract's values**, not extended JSON tags: an instant as microseconds, Decimal128 as a string, ObjectId as 24 hex characters, Binary as a `hex:` string.
- **The MongoDB reader runs apart from the consumer**, on the bounded queue MySQL has (`queue_capacity`, `queue_max_bytes`).
- **`ControlKind` is `#[non_exhaustive]`**, and `Renamed` carries its new name: `Renamed { to }`.
- **`ce-stream-mysql-binlog` is 0.2.0.** Its rows events have the public fields `partition_id` and, on an update, `source_partition_id`, and `EventHeader::parse_rows_event_common_header` returns `RowsEventHeader`.
- **The workspace `rust-version` stays 1.75**, and `ce-stream-postgres` builds on it. The CLI and `ce-stream-mongo` stay on 1.88.

## Fixed

- **MySQL: XA transactions are delivered.** Before, the rows of an XA transaction were never delivered and its prepared GTID never entered the executed set. The rows are kept in memory from `XA PREPARE`, delivered at `XA COMMIT` as one commit at that position, and dropped at `XA ROLLBACK`. The prepared GTID stays out of the executed set until its `XA COMMIT` is delivered, so a restart between the two makes the server send the prepared transaction again. An `XA COMMIT` whose rows were never read (prepared before capture first started, or its prepare purged) stops the stream with an error.
- **MySQL: purged binary logs are `Error::HistoryLost`.** On resume the source added the server's `gtid_purged` to the set it sent with the dump, so the server never refused and skipped what it had purged, with no error. A resume is now `HistoryLost` when the server has purged a transaction that is in neither the checkpoint's `gtid` nor its `baseline_gtid`. The server's own refusal of a dump (error 1236) is `HistoryLost` too. A checkpoint with no `baseline_gtid` (written before 0.2.0) cannot be judged: it resumes as before, with a warning.
- **`FileCheckpointStore` saves atomically.** It wrote in place, so a kill during the write left an empty file that every restart refused. A save writes a temporary file and renames it.

## What changes for a consumer

| With v0.5.0 | With v0.6.0 |
|-------------|-------------|
| `source.run_transactions`, with a callback that takes a `CommittedTransaction` | `source.run_deliveries`, with a callback that takes a `Delivery`: match `Delivery::Commit(txn)`, `Delivery::Progress { position }`, and `Delivery::Schema(schema)` |
| `txn.gtid`, `txn.gtid_set_after` | `position.at["gtid"]`, `position.after["gtid"]`, or `ce_stream_mysql::commit_gtid(&txn)` and `commit_gtid_set_after(&txn)` |
| `txn.source_position()` | `txn.position` |
| An empty MySQL commit advances your position | `Delivery::Progress` advances it, with the executed set in `position.after["gtid"]` |
| MongoDB's idle position as a commit with no events | `Delivery::Progress`, one match arm |
| An exhaustive match on `ControlKind` | A wildcard arm, with `Truncated`, `DefinitionChanged`, and `Message` handled where they matter to you |
| `ControlKind::Renamed` and `ControlEvent::renamed_to` | `ControlKind::Renamed { to }` |
| `IncludeList` and `FileCheckpointStore` from `ce_stream_mysql` | From `ce_stream_core` |
| `ce_stream_mysql::GateReport`; `validate_capture_gates` is `Err` on a failure | `ce_stream_core::GateReport` from `source.gate()` or `validate_capture_gates`; `.into_result()?` refuses on failures |
| A literal of `MysqlBinlogSource` or `MongoChangeStreamSource` | Add `confirm: new_confirm()`, from the same crate |
| A literal of `SourceConfig` without `..Default::default()` | Add `checkpoint: CheckpointMode::OnOk` |
| A literal of `ControlEvent` | Add `identity: None` |
| `HttpSink::post_committed_transaction(&txn)` | `HttpSink::post_delivery(&delivery)` |
| Your own comparison of GTID sets or cluster times against a seed target | `source.covers(at, target)`, over a target from `SeedCut::mark()` |
| `gtid_executed` read by hand for a seed cut | `MysqlSeedCut { seed, capture }.mark()`. Its `at` leaves out what the stream's server has purged |
| Nothing compares the stream server's purged set with your position | `Error::HistoryLost` from `run`, and `server_missing` when you choose among servers. A checkpoint made from a seed cut takes the mark's `after.baseline_gtid` as its `baseline_gtid` |
| MongoDB values classified from extended JSON tags | Classified from each value and its entry in the row's `types` |
| MySQL `hex:` strings for text that is not UTF-8, `ENUM` positions, `SET` bit masks | Text, labels, and labels joined by commas. Binary columns are always `hex:` |
| A JSON consumer in transaction mode reads a commit | It reads a `Delivery` and takes the commit from under `commit` |
| An Avro reader of `committed-transaction` v1 to v3 | v4 for commits, `progress-v1`, and `table-schema-v1`, told apart by `x-ce-stream-avro-schema` |
| A row-mode sink takes every CloudEvent as a row or DDL | It skips or uses `io.ce-stream.schema` |

Parts stay as v0.5.0 defined them. Two additions: a `Schema` may come between two parts of one transaction, and a transaction's controls go with its last part.

## PostgreSQL: known limits

As [`ops-e2e.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/ops-e2e.md#postgresql-prerequisites) and [`library.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/library.md#postgresql) have them:

- **Server:** at least `min_server_version` (default 17), `wal_level = logical`, a free slot and WAL sender. The account needs `REPLICATION`. Authentication is SCRAM-SHA-256.
- **Database:** not `SQL_ASCII`. One stream is one database, and a subject is `schema.table`.
- **Publication:** it publishes insert, update, delete, and truncate, with `publish_via_partition_root = false`.
- **Table:** in the publication with no row filter and no column list; a primary key; `REPLICA IDENTITY FULL`, on each partition too; not `UNLOGGED`, temporary, or foreign.
- **Generated columns:** none on 17. On 18, `publish_generated_columns = stored`.
- **The slot is yours to make and drop.** A missing or invalidated slot is `Error::HistoryLost`, never a quiet new slot, and so is a checkpoint behind the slot. Starting after the slot was lost means seeding again.
- **A stopped stream holds WAL.** Drop a slot you no longer need. The gate warns when `max_slot_wal_keep_size` is unlimited.
- **A drop or a rename sends nothing on the stream.** `catalog_tables` runs the query that shows them, on a connection you supply.
- **From a standby:** `hot_standby_feedback = on`, and making a slot waits until `SELECT pg_log_standby_snapshot()` runs on the primary. A seed cut always runs on the primary.
- **A failover slot is for a slot on the primary.** A checkpoint past the point where the new timeline forked is `Error::Checkpoint`. A server on an older timeline than the checkpoint's (an old primary) is refused.
- **TLS:** without `tls_ca`, TLS encrypts and checks nothing. An embedder installs a `rustls` crypto provider before connecting with TLS.

## Not supported

- PostgreSQL: `streaming = on`, two-phase decoding, the `binary` row format, and `publish_via_partition_root = true` (non-goals of [#19](https://github.com/AxialDB/ce-stream/issues/19)). A prepared transaction is decoded at `COMMIT PREPARED`.
- Automatic failover. Finding the new primary and what a lost change costs are the embedder's.
- Managed PostgreSQL services are not tested.
- SQL Server and SQLite. Their designs are restated against the contract in [`issues/19.md`](https://github.com/AxialDB/ce-stream/blob/main/docs/issues/19.md); there is no crate.
