# Release v0.4.0 — MongoDB change streams

**Date:** 2026-10-04  
**Tag:** [`v0.4.0`](https://github.com/AxialDB/ce-stream/releases/tag/v0.4.0)  
**Issue:** Closes [#5](https://github.com/AxialDB/ce-stream/issues/5) (MongoDB change stream source)

## Summary

ce-stream can tail a MongoDB 8.0+ replica set and deliver the same commit-boundary CloudEvents as the MySQL source. One node is enough. There is no Kafka, Debezium, or mongod plugin. MySQL JSON and Avro v1 output stay byte-identical to v0.3.0.

## Upgrade notes

### Breaking (struct literals)

`CommittedTransaction` gained `position` and `control`. MySQL leaves both empty. Existing literals need:

```rust
..Default::default()
```

`IncludeList` moved to `ce-stream-core`. `ce-stream-mysql` still re-exports it until v0.5.

`ce-stream-cli` and `ce-stream-mongo` require Rust 1.88. The rest of the workspace stays on 1.75.

### Mongo source

```toml
[source]
adapter = "mongo"
uri = "mongodb://127.0.0.1:27017/?replicaSet=rs0"
database = "app"
full_document = "required"   # or update_lookup
seed = false
include_tables = ["app.orders"]
```

- One change stream per database, with no server-side `$match`. The include list filters in this process.
- `full_document = "required"` needs post-images (`changeStreamPreAndPostImages`). `update_lookup` is the opt-out. Pre-images are never requested.
- Consecutive events with the same `(lsid, txnNumber)` are one commit. Other writes are their own commit.
- Drop or rename of a watched collection, dropDatabase, and invalidate end capture.
- `seed = true` copies included collections at a majority cluster time, then tails from that time.
- Restart with the saved `resume_token`. A token the server cannot find is history lost: reseed.

Sharded clusters (`mongos`) and MongoDB older than 8.0 are refused.

### Avro

Commits with a position or control events use `ce-stream.committed-transaction.v2`. MySQL commits stay on `ce-stream.committed-transaction.v1`. Row events stay `ce-stream.cloudevent.v1`.

## Install

### crates.io

Publish order is in [`releasing.md`](../releasing.md#cratesio). After that:

```bash
cargo install ce-stream-cli
```

Libraries: `ce-stream-core`, `ce-stream-mysql`, `ce-stream-mongo`. `ce-stream-mysql` depends on `ce-stream-mysql-binlog`, the MySQL 9.x fork of `mysql-binlog-connector-rust` (that upstream name is owned by another publisher; crates.io 0.3.3 does not include `SHOW BINARY LOG STATUS`).

### From Git tag

```bash
cargo install --git https://github.com/AxialDB/ce-stream --locked --tag v0.4.0 ce-stream-cli
```

### Pre-built binaries

GitHub Release assets are built in CI (**Linux** `ubuntu-latest` and **Windows** `windows-latest`). Verify `SHA256SUMS`.

## Verification

### CI (no database)

`fmt`, `clippy`, and `cargo test -p ce-stream-core -p ce-stream-mysql -p ce-stream-mongo`. The Release workflow compiles Linux and Windows binaries. There is no live MySQL or MongoDB in GitHub Actions.

### Lab

MongoDB 8.0.32 and one required-mode pass on 9.0.2: insert, update, replace, delete, multi-document transaction, resume, history lost, drop and rename, seed overlap. MySQL unit tests stayed green.

On this lab (WSL release client, databases on the build laptop, fast HTTP sink, one autocommit change per commit): MySQL JSON about 1,200–1,500 commits/s, MySQL Avro about 2,100 commits/s, Mongo JSON and Avro about 1,700–2,000 commits/s. With `sync_binlog=1` the MySQL container itself committed about 11 single-row transactions/s and capture stayed caught up.
