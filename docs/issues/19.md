# Issue #19 — One contract for every source, and `ce-stream-postgres`

**GitHub:** [AxialDB/ce-stream#19](https://github.com/AxialDB/ce-stream/issues/19)
**Label:** (feature)
**Status:** **Implemented on the branch, not released.** It stays on `issue-19/source-contract-and-postgres` until the PostgreSQL host and the other hosts of its first consumer (AxialDB) have been built on it. No version, tag, or release notes until then.

> **Resolution:** `ce-stream-core` says what every source delivers (`Delivery`), how positions compare (`covers`), how a consumer confirms (`Confirm`), how a seed lines up (`SeedCut`), and what a gate reports (`GateReport`). MySQL and MongoDB moved onto it, and `ce-stream-postgres` is the first source written against it.

The issue on GitHub has the full design. This page has what the build found.

## Where the build differs from the issue

- **A position compares by the end of a commit.** The issue has `covers` as `target.at.lsn <= at.after.lsn`, and a resume that drops a commit "at or below" the checkpoint. A commit record can start exactly where the one before it ended: in a crash loop with 4 writers, 1991 of 6000 commits did. Both rules would lose such a commit. `covers` compares `target.after.lsn <= at.after.lsn`, and a resume drops only a commit that starts below the checkpoint, as the server does (`SnapBuildXactNeedsSkip`). A part's target has no `after` and is covered once a position is past its commit's start.
- **`at` has no `end_lsn`.** The issue has `at = { lsn, end_lsn, xid }`. A part is delivered before its commit's end is known, and every part of a transaction has the same `at`, so `at = { lsn, xid }`. The end is `after.lsn`.
- **A mark's LSN is the same in the stream and from `mark()`.** `pg_logical_emit_message` returns the end of its record, and `pgoutput` sends that LSN.
- **The checkpoint store has two steps.** `save` is atomic and may run on every commit. `sync` makes it survive the machine. The slot moves only to what has been synced, once a second, so a checkpoint is never behind its slot after a power cut. An fsync per commit held the stream to about 4 commits a second on a lab disk; the same run does about 1000 now.

## What the crash loop found

`FileCheckpointStore` wrote in place, so a kill during the write left an empty file and every restart refused it. A save now writes a temporary file and renames it.

## What the lab found about the server

- **An announcement is not a signal of a rewrite.** The server announces a table again after anything that invalidates its cache entry, `VACUUM` and `ANALYZE` included. A repeated `Schema` says only "look again"; the file node and the column's row in `catalog_tables` say what happened.
- **A keepalive comes as soon as the server has passed what the client has confirmed**, not only at half of `wal_sender_timeout`, so a quiet stream learns its position within moments of an unpublished write.

| After | File node moves | Column's row moves | `DefinitionChanged` |
|-------|-----------------|--------------------|---------------------|
| `ADD COLUMN` | no | no | yes |
| `VACUUM`, `REINDEX`, `ANALYZE` | no | no | no |
| `VACUUM FULL`, `CLUSTER`, `TRUNCATE` | yes | no | no |
| `ALTER COLUMN ... TYPE` | yes | yes | yes |

The same on 17 and 18. The server announced the table again after each of them.

## Lab

Library tests, on PostgreSQL 17 and 18 (seed cut, durable ack, catalog and the table above, gate, keepalive order, prepared transactions, a checkpoint behind the slot):

```bash
export CE_STREAM_PSQL=/usr/lib/postgresql/17/bin/psql CE_STREAM_PG_PORT=5432
export CE_STREAM_PG_PASSWORD=... CE_STREAM_PG_CDC_PASSWORD=...
cargo test -p ce-stream-postgres --test live -- --ignored --test-threads=1
```

The crash run: [`scripts/crash-harness/postgres/`](../../scripts/crash-harness/postgres/README.md).

Run once by hand through the CLI, with these results:

| Check | Result |
|-------|--------|
| A sink blocked 30 s against `wal_sender_timeout = 10s`, 30,000 rows | All arrive; the stream stays attached (17, 18) |
| A TOASTed value an update left alone | Filled from the old row (17, 18) |
| A `LATIN1` database | Text matches the server's own conversion to UTF-8 (17) |
| A `SQL_ASCII` database | Refused by the gate (17) |
| Generated columns | Refused, then delivered after `publish_generated_columns = stored` (18) |
| Capture from a standby, with `pg_log_standby_snapshot()` on the primary | Slot made; rows and marks delivered (17) |
| TLS: no CA; the right CA | Encrypted, per `pg_stat_ssl` (17) |
| TLS: another CA; a certificate for another host; a server without TLS | Refused (17) |

Managed services are not tested.

## Other hosts on the contract

The SQL Server and SQLite designs have no crate yet. On the contract:

- **SQL Server:** a `SeedCut` on its own connection, `mark()` from `log_end_lsn`, `wait_settled()` on `sys.dm_tran_active_transactions`, `Progress` from the tail's read position, values as [`../values.md`](../values.md) says.
- **SQLite:** no queue, since the consumer runs on the write path, and `covers` answers `Err` across a restart, since its counter does not survive one.
