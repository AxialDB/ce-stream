# Issue #11 — Mongo: resume from a position on a collection that left the include list

**GitHub:** [AxialDB/ce-stream#11](https://github.com/AxialDB/ce-stream/issues/11)  
**Label:** bug  
**Status:** **Implemented** (pending merge; ships with [#9](9.md) in **v0.4.2**). Close with `Fixes #11` on the PR.

> **Resolution:** a stream opened after a resume token lets that one event through its server-side filter by `_id`. Found after #9 was merged and before v0.4.2 was tagged; no release has the fault.

The **Problem summary** below is the defect as reported. It is not current runtime behavior.

## Problem summary

With the server-side include filter of #9, capture could not resume from a position whose event the filter left out. The server answered `cannot resume stream; the resume token was not found` (code 280), which the source reports as `Error::HistoryLost`. The server looks for the event it resumes after once the filter has run.

It happened when the checkpoint was the token of an event of a collection that was no longer on the list:

- A listed collection was dropped. The `drop` event ends capture, its token is the checkpoint, and the embedder restarts without that collection.
- A table was taken off the list right after its last change, and capture restarted.
- Inside one run: the list lost one collection and gained another in the same step, and the last event read belonged to the one that left.

## Behavior

- A stream that is opened after a resume token adds one branch to its `$match`: `{ _id: <that token> }`. The server finds the event and starts after it. Every other event of that collection is still left out, and the event itself is never delivered.
- A post-batch token matches no event; the branch is harmless there.
- Checked with `mongosh` on 8.0.32 and 9.0.2: with the branch, an update in an unlisted collection without post-images still does not fail the stream.

## Non-goals (this issue)

- Keeping the old collection in the filter. It also works, and brings back that collection's events and its post-image requirement.

## Tests

- Unit: `source.rs`, `the_event_a_stream_resumes_after_passes_the_filter_by_its_id`.
- Live, not in CI: `crates/ce-stream-mongo/tests/server_filter_live.rs`, steps 5 to 7: a list that loses the collection of the last event read while it gains another, a drop of a listed collection, and the restart after that drop without the dropped collection.
