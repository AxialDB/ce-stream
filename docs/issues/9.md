# Issue #9 — Mongo: server-side include filter

**GitHub:** [AxialDB/ce-stream#9](https://github.com/AxialDB/ce-stream/issues/9)  
**Label:** bug  
**Status:** **Implemented** (pending merge + annotated tag **v0.4.2**). Close with `Fixes #9` on the PR.

> **Resolution:** a finite include list is sent to the server as a `$match`. When the list gains a collection, the stream is opened again at its last position with the wider filter, and `IncludeList::in_effect_allows` says when that has happened. Ship as **v0.4.2**.

The **Problem summary** below is the defect as reported. It is not current runtime behavior.

## Problem summary

The Mongo source opened its change stream on the whole database with no server-side filter and dropped the events of collections outside `include_tables` in this process. With `full_document = "required"`:

- An update or replace in any collection of the database without `changeStreamPreAndPostImages` ended the stream: "Change stream was configured to require a post-image for all update events, but the post-image was not found". The collection was not on the list. A restart from the checkpoint read the same event again, so capture could not get past it.
- Every write of the database was sent to the client. A bulk load into a collection that was not on the list delayed the listed collections until the stream had read through it. Measured with `mongosh` on 8.0.32 and 9.0.2: 14.4 s and 100,001 events to get past 100,000 inserts, against 0.4 s and 1 event with a `$match`.

`map.rs` gave the reason there was no filter: a `$match` fixed at start would hide collections added to the include list later.

## Behavior

- **Filter.** A finite include list opens the stream with one stage: `ns.coll` in the listed collections of the source database, or `operationType` in `dropDatabase`, `invalidate` (the two ending events that have no collection). An empty `include_tables` (every table) keeps the unfiltered stream.
- **A list that gains a collection.** Before each read the source compares the include list with the filter of the open stream. When the list asks for a collection the stream does not send, the stream is opened again with `resumeAfter` the last place read (the last event, or the post-batch token of an empty batch) and the wider filter. What follows that place arrives once, in order.
- **A list that loses a collection** needs no new stream. The filter in this process still drops those events, and still pins the list for the length of one transaction.
- **Acknowledgement.** `IncludeList::set_in_effect` (adapters) and `in_effect` / `in_effect_allows` (embedders), in `ce-stream-core`. The Mongo source reports the list its open stream filters by, after each open, and clears it when capture ends. Until `in_effect_allows("db.coll")` is true, changes to a collection that was just added may still be left out by the server. An embedder that copies a collection and then applies its changes waits for it before the copy. The MySQL adapter filters in this process and reports nothing.
- **Position on an idle list.** The server no longer sends the writes of other collections, so they no longer produce commits. To keep the checkpoint moving past them, an empty batch whose post-batch token has moved is delivered as a commit with no events and that token as its position. Its `cluster_time` is read from the token. Without this a restart after a long quiet time would resume from a place the oplog may no longer hold.
- **`getMore` wait.** `maxAwaitTimeMS` is 250 ms, so a changed list is noticed within that time.

## Non-goals (this issue)

- Narrowing the server filter when the list shrinks.
- A filter for the ending events of other collections: `drop` and `rename` of a collection that is not listed are left out by the server now; they only advanced the resume token before.
- `rename` of another collection onto a listed name (`to.coll`): not delivered before, not delivered now.
- One stream per collection.

## Tests

- Unit: `source.rs` (the stage, what needs a new stream, the acknowledgement is cleared), `group.rs` (`an_idle_batch_hands_out_a_position_that_moved_and_only_once`), `checkpoint.rs` (`a_resume_token_gives_its_cluster_time`), `include.rs` (`in_effect_is_what_the_adapter_reported`). CI: `cargo test -p ce-stream-core -p ce-stream-mongo`.
- Live, not in CI: `crates/ce-stream-mongo/tests/server_filter_live.rs`. An update in a collection without post-images that is not listed; a list that gains a collection, with every later change arriving once and in order; the position moving past a bulk load into an unlisted collection; a restart from that position; a drop of a listed collection.

  ```bash
  CE_STREAM_MONGO_URI="mongodb://127.0.0.1:27017/?replicaSet=rs0" \
    cargo test -p ce-stream-mongo --test server_filter_live -- --ignored --test-threads=1
  ```

  `CE_STREAM_MONGO_URI_2` runs the same scenario against a second replica set.
