# Issue #1 — Transaction-boundary checkpointing

**GitHub:** [ce-stream/ce-stream#1](https://github.com/ce-stream/ce-stream/issues/1)  
**Label:** bug  
**Status:** **Implemented** (pending merge + annotated tag **v0.2.0**). Close with `Fixes #1` on the PR.  
**Gate:** Gate 0 (correctness) before AxialDB CDC embedding

> **Resolution:** Commit-boundary buffering, XID-gated emit/checkpoint, GTID resume handshake, `delivery_unit`, DDL, and compressed txn unpack. Ship as **v0.2.0**. Do not treat GitHub issue #1 as closed until the PR merges.

The **Problem summary** below is the original defect write-up (pre-fix). It is not current runtime behavior.

---

## Problem summary

`MysqlBinlogSource` treats the delivery/checkpoint unit as a **single row CloudEvent**, not a MySQL transaction. Today:

1. On `EventData::Gtid`, the GTID is added to the executed set immediately.
2. Each row emits `StreamMsg::Event { event, gtid_set }`; on consumer `Ok`, the full GTID set (including the in-flight GTID) is persisted.
3. `EventData::Xid` is a no-op.
4. Filtered tables emit `StreamMsg::Advance { gtid_set }` mid-transaction.
5. **`TransactionPayload` ignored:** with `binlog_transaction_compression=ON` (MySQL 8+), compressed transactions hit the catch-all at `lib.rs:283` and are **silently dropped** — no rows, no error.

**Failure modes:**

- **Mid-txn checkpoint:** crash after row 1 of an N-row transaction → checkpoint contains GTID `G` → restart skips `G` entirely → rows 2..N are **silently lost**. This violates the at-least-once contract in [`delivery.md`](../delivery.md) for stateful consumers of full row images.
- **Compressed txn drop:** entire transactions vanish when compression is enabled (common on MySQL 8 production).

## Root cause (code)

| Step | Location | Behavior |
|------|----------|----------|
| GTID added early | `crates/ce-stream-mysql/src/lib.rs:223–226` | `tracker.add_gtid(&g.gtid)` at GTID event |
| Per-row checkpoint | `lib.rs:150–153` | `on_event(event)?` then `persist_gtid_set(&gtid_set)` |
| XID ignored | `lib.rs:279–281` | comment only; no commit gate |
| Filtered advance | `lib.rs:345–351` | `Advance { gtid_set }` persists mid-txn set |
| GTID set holes | `crates/ce-stream-mysql/src/map.rs:51–100` | `GtidTracker` stores max gno → serializes `uuid:1-{max}` |
| Compressed txns | `lib.rs:283` | `TransactionPayload` falls into catch-all `ignored` |
| DDL | `lib.rs:283` | `Query` events ignored |

## Goals

1. **Correct delivery boundary:** a GTID enters the durable executed set only after the **entire MySQL transaction** is delivered and acknowledged.
2. **Commit-boundary emit:** buffer binlog rows until XID; consumer sees nothing mid-transaction regardless of `delivery_unit`.
3. **Delivery unit knob:** `row` (N CloudEvents after commit) or `transaction` (one `CommittedTransaction` envelope) — same config for CLI and embedders.
4. **At-least-once semantics:** crash mid-transaction → on resume, **re-deliver the whole transaction** (duplicate rows OK; missing rows not OK).
5. **Interval-correct GTID sets:** preserve holes; never collapse to `1..max`.
6. **Compressed transactions:** unpack `TransactionPayload` or hard-fail with a clear error.
7. **DDL visibility:** schema-affecting commits surface as an ordered barrier (minimal v1 shape acceptable).
8. **Hard-gate validation:** connect-time checks for safe ROW capture settings.

## Non-goals (this issue)

- Exactly-once delivery
- Cross-transaction ordering guarantees beyond binlog order
- Mid-transaction row streaming (rows visible before commit)
- Confluent Schema Registry / per-table typed Avro column schemas
- Phase 6 multi-DB adapters

## Proposed API

### Core (`ce-stream-core`)

Add delivery unit config and transaction envelope types:

```rust
// crates/ce-stream-core/src/source.rs

/// What the consumer receives per MySQL commit (after XID).
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum DeliveryUnit {
    /// N row CloudEvents per commit, emitted in order **after** XID (default).
    #[default]
    Row,
    /// One `CommittedTransaction` envelope per commit.
    Transaction,
}

pub struct SourceConfig {
    // ... existing fields ...
    pub delivery_unit: DeliveryUnit,
}
```

```rust
// crates/ce-stream-core/src/transaction.rs (new)

pub struct CommittedTransaction {
    /// GTID of this commit, e.g. "3e11fa47-71ca-11e1-9e33-c080020c9a66:1"
    pub gtid: String,
    /// Executed GTID set **after** this transaction commits (for checkpoint resume).
    pub gtid_set_after: String,
    /// DDL in binlog order, **before** row events (same logical content as DDL CloudEvents in row mode).
    pub ddl: Vec<DdlStatement>,
    /// Row change events in binlog order (same CloudEvent shape as today).
    pub events: Vec<CloudEvent>,
}

pub struct DdlStatement {
    pub schema: String,
    pub query: String,
}
```

**Consistency invariant:** one commit with DDL + N rows surfaces the same sequence in both modes — DDL first, then rows — either as envelope fields or as separate CloudEvents.

Extend `ChangeSource` — config selects which callback is used; **both buffer until XID**:

```rust
// crates/ce-stream-core/src/source.rs

#[async_trait]
pub trait ChangeSource: Send {
    /// Row mode: after XID, called for each DDL CloudEvent then each row CloudEvent.
    /// All messages from one txn are delivered back-to-back before the next txn begins.
    async fn run<F>(&mut self, mut on_event: F) -> Result<()>
    where
        F: FnMut(CloudEvent) -> Result<()> + Send;

    /// Transaction mode (`delivery_unit = Transaction`): called once per commit.
    async fn run_transactions<F>(&mut self, mut on_txn: F) -> Result<()>
    where
        F: FnMut(CommittedTransaction) -> Result<()> + Send;
}
```

Implementation reads `config.delivery_unit` and rejects mismatched entry points (e.g. `run()` when unit is `Transaction`).

**Config (CLI and embedders — same knob):**

```toml
[source]
delivery_unit = "row"         # default — one CloudEvent per HTTP POST
# delivery_unit = "transaction"  # one CommittedTransaction per POST (AxialDB)
```

**Compatibility:** default `delivery_unit = row` preserves today's wire shape (one CloudEvent per message). **Semantic change:** rows are no longer emitted as binlog row events arrive — only after XID. Document in `CHANGELOG.md`.

**Checkpoint payload:** keep `{ "gtid": "<set string>" }` shape. Value is `gtid_set_after` from the last acknowledged commit. Optional debug field `"last_committed_gtid"` — not required for resume.

### Delivery model (unit × encoding)

**Invariant:** the source always buffers until XID. The knob only controls what crosses the consumer boundary at commit time.

| `delivery_unit` | After XID | Wire messages (DDL + N-row txn) | Checkpoint |
|-----------------|-----------|----------------------------------|------------|
| `row` (default) | DDL CloudEvents, then row 1…N in order | M DDL messages + N row messages (JSON or Avro) | After all M+N acks |
| `transaction` | Emit one envelope | 1 message (JSON or Avro `committed-transaction-v1`) | After 1 ack |

JSON and Avro are parallel encodings of whichever unit is selected — same semantics, different serializer. CLI and embedders use the same `SourceConfig.delivery_unit`; no separate “embedder path.”

| A.4 | Unit tests: round-trip `abc:1-10,abc:12-15`; add `abc:11` → `abc:1-15`; reject/ignore duplicate adds. Port key cases from `vendor/.../gtid_set.rs:254–457`. |

**Acceptance:** `to_set_string()` never emits false contiguous ranges across holes.

### Phase B — Transaction buffer + commit gate (core fix)

**Files:** new `crates/ce-stream-mysql/src/txn_buffer.rs`; refactor `lib.rs`.

#### B.1 — State machine

```
Idle
  → Gtid(G): pending = G, ddl_buffer = [], row_buffer = []
  → Query(DDL)*: append DdlStatement (and prepare matching DDL CloudEvent for row mode)
  → Row*: append CloudEvent(s) to row_buffer only — **no consumer emit**
  → Xid: flush (delivery_unit selects shape):
         row:         for ddl_ev in ddl_events { on_row(ddl_ev)? };
                      for ev in row_buffer { on_row(ev)? }
         transaction: on_txn(CommittedTransaction { gtid: G, ddl, events: row_buffer, ... })?
         (gtid_set_after = executed ∪ {G}; G NOT in executed until full ack)
  → all callbacks Ok: executed.add_committed(G); persist gtid_set_after
  → any Err: do not persist; full txn redelivered on reconnect
```

| Task | Detail |
|------|--------|
| B.2 | Replace `StreamMsg::Event`/`Advance` with internal commit flush at XID only. |
| B.3 | Remove `tracker.add_gtid` from GTID handler (`lib.rs:225`). |
| B.4 | On XID: always close the pending GTID. Emit a commit even when both `ddl` and `events` are empty (no-op / all-filtered). Empty commits still ack → merge GTID into executed set (source-resume watermark). |
| B.5 | **Filtered rows:** do not emit `Advance` mid-txn. At XID, emit commit with whatever included `ddl`/`events` were buffered (possibly both empty). |
| B.6 | Add `DeliveryUnit` to `SourceConfig`; wire row vs transaction flush from `config.delivery_unit`. |
| B.7 | CLI: read `source.delivery_unit` from TOML; branch sink emit (per-event vs txn envelope). Update `embed_callback.rs` example. |
| B.8 | **Post-XID ack rule (row mode):** fan out DDL CloudEvents then row CloudEvents; **do not** `add_committed` / persist until **all** of those callbacks return Ok. Crash mid-fan-out → no checkpoint → full txn redelivery. Never reintroduce per-message checkpoint inside the post-commit fan-out. |

**Acceptance:** synthetic test — GTID + DDL + 3 rows + XID; **zero** consumer calls before XID; row mode → 1 DDL CloudEvent + 3 row calls after XID then **one** checkpoint; transaction mode → 1 envelope with `ddl.len()==1` and 3 events; simulated crash after first post-XID ack does **not** persist.

### Phase D — DDL visibility (first-class in both modes)

**Files:** new `crates/ce-stream-mysql/src/ddl.rs`; CloudEvent mapping helper.

DDL is a **first-class commit resident**, not an optional transaction-mode-only side channel. Both delivery units expose the same real binlog `Query` DDL; only packaging differs.

| Task | Detail |
|------|--------|
| D.1 | Match `EventData::Query(q)` when query is DDL (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME` — case-insensitive prefix). |
| D.2 | Append `DdlStatement { schema, query }` to in-flight txn DDL buffer. |
| D.3 | **Transaction mode:** put `ddl` on `CommittedTransaction` **before** `events`. |
| D.4 | **Row mode:** emit one DDL CloudEvent per `DdlStatement` **before** row CloudEvents (same order as envelope fields). |
| D.5 | Ignore `BEGIN`/`COMMIT`/`ROLLBACK` query text. |
| D.6 | **DDL-only commits:** XID with non-empty `ddl` and empty `events` still emits (envelope or DDL CloudEvents only) then checkpoints after full ack. |
| D.7 | DDL CloudEvent: `type = io.ce-stream.mysql.ddl`, `data = { "schema", "query" }`, same binlog extensions as row events (`gtid`, etc.). Avro: JSON payload in existing cloudevent wrapper (same pattern as rows). |
| D.8 | Richer barrier fields (stable table incarnation / schema epoch / mapping version) remain **consumer** responsibilities for Gate 0; ce-stream ships `schema` + `query`. |

**Acceptance:** (1) DDL + 3 rows → transaction mode: one envelope; row mode: 1 DDL CE + 3 row CEs; (2) DDL-only → envelope with empty events / DDL CEs only.

## Open questions for review

1. **Default `delivery_unit`:** **Resolved — keep `row` default** (CLI/HTTP wire-compat); AxialDB embed sets `transaction`.
2. **DDL shape:** **Resolved — first-class in both modes.** Transaction: `CommittedTransaction.ddl` then `events`. Row: DDL CloudEvents then row CloudEvents. Same logical order; packaging differs only.
3. **DDL richness:** **Resolved — `{ schema, query }` only for Gate 0.** AxialDB derives impact / table identity / schema epoch. Richer ce-stream barrier fields are a follow-up if needed.
4. **Breaking change notice:** **Resolved — release as `v0.2.0`.** Post-commit emit + new delivery API are a minor bump, not a patch.
5. **Vendor `GtidSet`:** **Resolved — internal-only wrapper.** Checkpoint / `gtid_set_after` remain strings; do not public-re-export vendor GTID types.

**Resolved in this plan:**

- Unified `delivery_unit` for CLI and embedders; no separate consumer paths.
- Default `delivery_unit = row`; AxialDB sets `transaction` at embed time.
- `CommittedTransaction` struct (not CloudEvent wrapper) for transaction mode.
- Anonymous / missing-GTID streams hard-fail in v1.
- Hard-fail when `binlog_row_metadata != FULL` (and other Gate 0 variables as listed).
- Empty / all-filtered / DDL-only commits still advance the executed set at XID.
- DDL is first-class in **both** delivery units (same logical order: DDL then rows).
- DDL payload richness for Gate 0 is `{ schema, query }` only.
- Ship this work as **`v0.2.0`**.
- Vendor `GtidSet` stays private behind an internal wrapper.
