## Problem summary

ce-stream reads MySQL 9.x binlogs only. Embedders that keep derived state from MongoDB need Kafka plus a connector, or their own oplog tailer (not possible on Atlas). `ce-stream-core` is also MySQL-shaped: `CommittedTransaction` carries `gtid` / `gtid_set_after`, `DdlStatement` is SQL text, and `IncludeList` lives in `ce-stream-mysql`.

## Behavior

Core (MySQL output unchanged):

- `CommittedTransaction.position: Option<SourcePosition>` (`adapter`, `at`, `after`). MySQL leaves it `None` and keeps `gtid` / `gtid_set_after`, so MySQL JSON and Avro output are byte-identical to v0.3. `source_position()` derives MySQL's position: `at = {"gtid": gtid}`, `after = {"gtid": gtid_set_after}`. `after` is always the checkpoint payload that resumes after the commit. **Done** (commit 1).
- `CommittedTransaction.control: Vec<ControlEvent>` (`dropped`, `renamed`, `database_dropped`, `invalidated`), CloudEvent types `io.ce-stream.control.*`. Empty for MySQL, which keeps `DdlStatement`. Avro `committed-transaction-v1` refuses commits with `position` or `control` set. **Done** (commit 1).
- `IncludeList` / `IncludeFilter` move to `ce-stream-core`; `ce-stream-mysql` re-exports `IncludeList` until v0.5. **Done** (commit 1).
- `CommittedTransaction` derives `Default`: struct literals add `..Default::default()`.

`ce-stream-mongo`:

- MongoDB 8.0+ replica set (one node is enough). Standalone is refused at connect.
- One stream per source database, no server-side `$match`. A `$match` fixed at start would hide collections added later. The include list filters in this process and is pinned for the length of one transaction. **Done** (crate).
- `fullDocument: "required"` (post-images) by default; `"updateLookup"` opt-out. Pre-images never requested.
- insert / update / replace / delete map to `ChangeOp`. drop and rename of a watched collection, plus dropDatabase and invalidate, emit the control event and end capture. A drop of a collection that is not watched only advances the resume token.
- Transactions: consecutive events with the same `(lsid, txnNumber)` are one commit. A group closes on the next different transaction, or when an empty batch advances `postBatchResumeToken` past it.
- Checkpoint payload: `resume_token`, `cluster_time`, `seed_cluster_time`. `ChangeStreamHistoryLost` is a distinct error.
- Seed helper: cluster time `T`, majority-read scan, stream from `T`.
- Connect gates: replica set, 8.0+, `find` + `changeStream`, post-images in `required` mode, oplog window when `clusterMonitor` is granted.
- Explicit BSON to JSON for `ObjectId`, `Decimal128`, `Date`, `Binary`, 64-bit integers.
- CLI `source.adapter = "mongo"`, including `sink.format = "avro"` (`committed-transaction-v2` when a commit has a position or control events; row events stay `cloudevent-v1`). MySQL Avro stays v1.
- Seed: one majority find for cluster time T (`ping` rejects readConcern), then a majority cursor in batches of 512. The change stream starts at T. The collection is not loaded into one buffer.

## Non-goals (this issue)

- Sharded clusters (`mongos`)
- MongoDB older than 8.0
- Live MongoDB tests in CI
- Avro `committed-transaction-v1` changes

## Tests

CI: unit tests for event mapping, transaction grouping, BSON conversion, and MySQL position fields (`cargo test -p ce-stream-core -p ce-stream-mysql -p ce-stream-mongo`).

Lab (ignored by default, `mongo:8.0.32` one-node replica set): insert, update, replace, delete, multi-document transaction, resume after restart, history lost, drop and rename, seed overlap with concurrent writes. Both `required` and `update_lookup`. One `required` pass on `mongo:9.0.2` before release.
